# 대기 명단 직접 운영 서버 설계 (1판)

2026-11-28 작성. 설계만 담았고 아직 아무것도 배포하지 않았습니다. 이 저장소는 공개이므로 이 문서에는 비밀 값(키, 토큰, 개인 주소)을 적지 않습니다.

가격과 한도는 2026-11-28에 각 회사의 공식 가격 페이지에서 확인한 값입니다. 법률 부분은 제가 아는 범위의 정리이고 변호사 검토를 거치지 않았습니다. 확인하지 못한 것은 9번에 따로 모았습니다.

## 0. 결론 먼저

- 서버 자체는 결제 확률을 올리지 않습니다. 대기 명단만 보면 지금의 구글폼이나 뉴스레터 서비스가 더 싸고 더 안전합니다.
- 그래도 지금 만드는 이유는 두 가지뿐입니다. 1월의 유료 알림은 서버 없이는 돌아가지 않고, 확인 메일을 거친 등록 수만 수요 증거로 쓸 수 있습니다.
- 추천 구성은 Cloudflare Workers(서버)와 D1(데이터베이스), Turnstile(봇 방지), Resend(메일 발송), 그리고 AFMX 전용 도메인입니다. 처음 비용은 도메인 값(연 1~2만 원대, 이름에 따라 다름)뿐입니다.
- 가장 큰 숨은 조건은 도메인입니다. 전용 도메인이 없으면 확인 메일을 보낼 수 없습니다. 지금 주소(github.io)로는 불가능합니다.
- 일은 대기 명단에 필요한 최소한으로 묶습니다. 로그인, 관리 화면, 결제는 1월 전에는 만들지 않습니다. 출시까지 9주가 남았고 이 작업에 1~2주 넘게 쓰면 손해입니다.

## 1. 약점과 위험

1. **결제와 거리가 멉니다.** 결제 없는 등록 수는 약한 수요 증거입니다. 서버를 잘 만들어도 그 사실은 바뀌지 않습니다. 이 작업이 값을 하는 것은 1월 유료 알림의 토대가 될 때뿐입니다.
2. **책임이 우리에게 옵니다.** 지금은 구글이 보관과 보안을 맡습니다. 옮기면 이메일 보관, 접근 통제, 사고 대응, 삭제 처리가 전부 운영자 한 사람의 일이 됩니다. 유출이 나면 한국 개인정보 보호법은 알게 된 때부터 72시간 안에 본인에게 알리도록 하고, 해킹처럼 밖에서 불법으로 접근한 유출은 인원과 상관없이 개인정보보호위원회나 KISA에 신고하도록 합니다(시행령 40조, 조문 직접 대조는 못 함).
3. **확인 메일을 넣으면 등록 수가 줄어듭니다.** 확인 링크를 누르지 않는 사람이 생깁니다. 줄어드는 비율은 재 봐야 압니다. 숫자는 작아지지만 믿을 수 있게 됩니다.
4. **새 도메인의 메일은 스팸함에 가기 쉽습니다.** 발송 이력이 없는 도메인이라 그렇습니다. 확인 메일이 스팸함에 가면 진짜 사람도 빠집니다. SPF, DKIM, DMARC 설정과 등록 직후 화면의 "스팸함도 확인해 주세요" 안내가 필수입니다.
5. **메일 관련 법이 따라옵니다.** 회원제 개시 안내 메일은 광고성 정보에 해당할 가능성이 큽니다. 한국 수신자에게는 제목에 (광고) 표시, 보낸 사람 정보, 무료 수신 거부 방법이 필요합니다(정보통신망법 50조). 미국의 CAN-SPAM 법은 상업 메일에 실제 우편 주소를 적도록 합니다. 1인 운영이면 집 주소를 적어야 한다는 뜻이라, 사서함이나 주소 대행을 구해야 할 수 있습니다. 이 항목은 변호사 확인이 필요합니다.
6. **무료 한도에 함정이 있습니다.** Resend 무료는 하루 100통입니다. 확인을 마친 구독자가 100명을 넘으면 주간 글을 하루에 다 보낼 수 없어 월 20달러 요금제가 필요합니다. D1 무료는 2026-09-01부터 하루 한도를 넘으면 자정(UTC)까지 조회가 실패합니다. 우리 규모에서는 닿기 어렵지만 봇 공격을 받으면 닿을 수 있어 봇 방지가 먼저 걸러야 합니다.
7. **개인정보 안내를 먼저 고쳐야 합니다.** 지금 안내문은 "Google Forms, 미국"이라고 적혀 있습니다. 보관 장소가 바뀌는 날 안내문도 같이 바뀌어야 하고, 삭제 기한 같은 기존 약속은 그대로 지켜야 합니다.
8. **주소가 바뀝니다.** 전용 도메인으로 옮기면 이미 공유한 github.io 링크는 자동으로 넘어가지만, 검색 노출과 미리보기 이미지는 다시 확인해야 합니다.

## 2. 대안 비교

| 안 | 좋은 점 | 나쁜 점 | 판단 |
|---|---|---|---|
| A. Cloudflare Workers + D1 + Resend | 거의 무료, 1월 유료 알림까지 한 곳에서 자람, 자료를 통째로 내려받을 수 있음 | 보안과 법적 책임이 전부 우리 몫, 만들 것이 가장 많음 | **추천** |
| B. Supabase | 로그인 기능이 들어 있어 회원제에 편함 | 무료 요금제는 한동안 안 쓰면 멈춘다고 알려져 있음(이번에 재확인 못 함), 메일 발송은 어차피 따로 필요 | 1월에 로그인을 만들 때 다시 비교 |
| C. 뉴스레터 서비스(Kit, Buttondown 등) | 확인 메일, 수신 거부, 발송 평판을 다 해 줌. 가장 빠르고 안전 | 섹터·종목별로 골라 보내는 알림은 어차피 직접 만들어야 함. 구독자 수에 따라 요금이 오름 | 대기 명단만이면 이쪽이 낫지만, 1월에 다시 옮겨야 함 |
| D. 구글폼 유지 | 일이 없음 | 확인 메일과 봇 방지가 없어 숫자를 믿을 수 없음. 삭제를 손으로 해야 함 | 1월까지 미루면 그때 한꺼번에 급해짐 |

A를 추천하는 근거는 "1월에 어차피 필요하다" 하나입니다. 유료 알림 계획이 미뤄지면 C가 더 맞습니다.

## 3. 구성

```
방문자 브라우저
   │  alerts.html (지금처럼 정적 페이지)
   ▼
api.<도메인>  Cloudflare Worker
   ├─ Turnstile 검증 (봇 방지)
   ├─ D1 (명단 저장)
   └─ Resend (확인 메일, 안내 메일)
```

- 공개 페이지는 지금처럼 GitHub Pages에 둡니다. 서버는 등록, 확인, 삭제만 맡습니다. 서버가 죽어도 공개 기록은 그대로 보입니다.
- 서버 코드는 새 비공개 저장소에 둘 것을 추천합니다. 유료 기능은 별도 비공개 저장소에 두기로 이미 정했고, 이 서버가 그 유료 기능으로 자라기 때문입니다. 비공개 저장소는 사용자 계정에서 직접 만들어야 합니다.
- 배포는 GitHub Actions가 합니다. 핸드폰에서 명령어를 칠 일이 없습니다.

### 주소 4개

| 주소 | 하는 일 |
|---|---|
| `POST /v1/waitlist` | 등록을 받습니다. 형식 검사, 봇 검사 뒤 "확인 대기"로 저장하고 확인 메일을 보냅니다. 이미 등록된 주소든 아니든 같은 답을 돌려줍니다(남의 등록 여부를 알아낼 수 없게). |
| `GET /v1/confirm` | 확인 메일의 링크입니다. 버튼이 있는 화면을 보여 주고, 버튼을 눌러야 확인됩니다. 메일 서비스의 자동 링크 검사가 대신 눌러 확인되는 일을 막습니다. |
| `POST /v1/remove` | 삭제 요청입니다. 그 주소로 삭제 링크를 보내고, 본인이 누르면 바로 지웁니다. 모든 메일 아래에도 같은 삭제 링크를 넣습니다. |
| `POST /v1/unsubscribe` | 메일 프로그램의 수신 거부 버튼이 부르는 주소입니다(한 번에 수신 거부). |

여기에 하루 한 번 도는 정리 작업이 있습니다. 7일 안에 확인하지 않은 등록을 지우고, 보관 기한이 지난 것을 지우고, 공개용 합계를 계산합니다.

### 저장하는 것

| 표 | 내용 |
|---|---|
| subscribers | 이메일, 상태(확인 대기, 확인됨, 수신 거부), 언어, 주간 글 수신 여부, 등록 시각, 확인 시각, 동의한 문장의 판 번호 |
| interests | 고른 섹터와 종목 (한 줄에 하나) |
| tokens | 확인·삭제 링크의 토큰. 원문이 아니라 해시만 저장, 유효 기간 있음, 한 번 쓰면 끝 |
| mail_log | 누구에게 어떤 메일을 언제 보냈는지 (안내 메일은 한 번만 보낸다는 약속을 지키는 근거) |
| suppression | 반송되거나 스팸 신고가 들어온 주소의 해시 (다시 보내지 않기 위해) |

1월에 더할 것: members(요금제, 결제 상태, 갱신일), 알림 발송 대기열, 로그인 세션.

저장하지 않는 것: IP 주소, 브라우저 정보, 보유 수량, 비밀번호. 로그인은 1월에 메일 링크 방식으로 만들어 비밀번호를 아예 갖지 않습니다.

### 봇 방지 세 겹

1. Turnstile: 사람에게는 거의 보이지 않는 검사입니다. 무료입니다.
2. 숨긴 입력 칸: 사람 눈에는 안 보이고 봇만 채우는 칸입니다.
3. 확인 메일: 메일함을 실제로 가진 사람만 "확인됨"이 됩니다. 수요로 세는 숫자는 이것뿐입니다.

여기에 같은 주소로 하루 3통 넘게 확인 메일을 보내지 않는 제한을 둡니다. 남의 주소를 넣어 메일 폭탄으로 쓰는 것을 막기 위해서입니다.

| 계정 지키기 | Cloudflare, GitHub, Resend, 도메인, 받는 메일함 전부 2단계 인증을 켭니다. 이 중 하나가 뚫리면 명단이 통째로 나갑니다. |
| 접근 줄이기 | 관리 화면을 만들지 않습니다. 명단은 Cloudflare 화면에서만 봅니다. 공격받을 문을 하나 줄입니다. |
| 삭제 | 본인이 링크를 누르면 즉시 지웁니다. "10일 안"이라는 지금 약속보다 빨라집니다. |
| 백업에 남는 것 | D1 무료는 지난 7일의 상태로 되돌릴 수 있습니다. 지운 자료도 그 기간에는 복구용으로 남으므로 안내문에 "삭제 뒤 최대 7일(유료 전환 시 30일) 동안 복구용 사본에 남는다"고 적습니다. |
| 보관 기한 | 지금 약속 그대로입니다. 회원제가 열린 뒤 12개월 안, 2027-12-31까지 안 열리면 그때 삭제. 정리 작업이 날짜를 보고 자동으로 지웁니다. |
| 안내문 고치기 | 보관 장소를 Cloudflare로, 메일 발송을 Resend로 바꿔 적고 두 회사 모두 국외 이전으로 알립니다. 서버 전환과 같은 날 바꿉니다. |
| 사고 대응 | 한 장짜리 순서를 미리 적어 둡니다. 키 교체, 범위 확인, 72시간 안에 본인 통지와 신고. |
| 합계 공개 | 지금 약속대로 10명 미만이 고른 항목은 공개하지 않습니다. 확인된 등록만 셉니다. |

## 5. 비용

| 항목 | 무료 한도 (2026-11-28 확인) | 넘으면 |
|---|---|---|
| Cloudflare Workers | 하루 요청 10만 건 | 월 5달러 |
| Cloudflare D1 | 하루 읽기 500만 줄, 쓰기 10만 줄, 저장 5GB(데이터베이스 하나는 500MB) | Workers 유료(월 5달러)에 포함 |
| Turnstile | 무료 | 해당 없음 |
| Resend | 월 3,000통, 하루 100통, 도메인 3개 | 월 20달러(5만 통, 하루 제한 없음) |
| 도메인 | 없음 | 연 1~2만 원대부터, 이름에 따라 다름 (이번에 가격 확인 못 함) |
| 받는 메일(Cloudflare Email Routing) | 무료 | 해당 없음 |

- 지금부터 확인된 구독자 100명 전까지: 도메인 값만 듭니다.
- 100명을 넘으면: 월 20달러(Resend). 유료 알림을 시작하면 Workers 유료까지 월 25달러 안팎입니다.
- 수익 모델 계산에서 가정한 고정비 월 50달러 안에 들어옵니다.
- Cloudflare 자체 메일 발송은 2026년 4월부터 공개 베타이고 Workers 유료 요금제에서만 일반 수신자에게 보낼 수 있습니다(월 3,000통 포함, 이후 1,000통에 0.35달러). 유료로 넘어가는 시점에 Resend와 다시 비교합니다.

## 6. 기존 구글폼 등록 옮기기

지금은 베타이고 실제 사용자가 아직 없으므로 옮길 양은 적거나 없을 것입니다. 순서는 이렇습니다.

1. 새 서버를 열고 페이지의 등록 칸을 새 서버로 돌립니다. 같은 날 개인정보 안내를 고칩니다.
2. 사용자가 구글 응답 시트를 직접 열어 줄 수를 확인합니다.
3. 삭제 요청(`| remove`)이 있는 주소는 먼저 뺍니다.
4. 남은 주소가 지인 몇 명이면 직접 다시 등록해 달라고 부탁합니다. 그보다 많으면 "확인 대기"로 넣고 확인 메일을 한 통만 보냅니다. 누르지 않으면 7일 뒤 지워집니다.
5. 구글폼의 응답 받기를 끄고, 응답과 시트를 지웁니다. 이 단계는 되돌릴 수 없으므로 사용자가 직접 합니다.

시트 파일을 저장소나 대화창에 올리지 않습니다. 이메일 주소가 공개 저장소에 들어가면 안 됩니다.

## 7. 사용자가 직접 만들 계정 (핸드폰으로 가능)

순서대로 하면 됩니다. 각 단계에서 나오는 비밀 값은 대화창이 아니라 지정된 설정 칸에만 넣습니다.

1. **도메인 이름 정하기.** AFMX가 들어간 이름으로 후보를 2~3개 고릅니다. 살 수 있는지와 가격은 2번 계정 안에서 바로 확인됩니다.
2. **Cloudflare 계정 만들기.** 가입한 뒤 바로 2단계 인증을 켭니다.
3. **Cloudflare 안에서 도메인 사기.** 카드 결제가 필요합니다. 이 프로젝트에서 처음 생기는 지출입니다.
4. **받는 메일 주소 만들기.** Cloudflare의 Email Routing에서 `hello@도메인`, `privacy@도메인`이 개인 메일함으로 넘어오게 합니다. 개인정보 안내에 적을 공개 연락처 문제가 여기서 같이 풀립니다. 학교 주소를 공개하지 않아도 됩니다.
5. **Resend 계정 만들기.** 4번에서 만든 주소로 가입하고 도메인을 등록합니다. 화면에 나오는 DNS 값 몇 줄을 Cloudflare에 넣어야 하는데, 이 단계는 화면을 보며 같이 진행하겠습니다.
6. **Turnstile 만들기.** Cloudflare 안에서 위젯을 하나 만들면 공개 키와 비밀 키가 나옵니다.
7. **비공개 저장소 만들기.** GitHub에서 비공개 저장소를 하나 만들고 이 프로젝트에 연결합니다.
8. **비밀 값 넣기.** Cloudflare 배포 토큰, Resend 키, Turnstile 비밀 키를 그 저장소의 Settings, Secrets 칸에 넣습니다.

1월에 더할 것: 결제 대행 계정(Paddle 추천), 사업자등록과 통신판매업 신고. 이 둘은 따로 정리가 필요합니다.

Claude가 맡는 것: 서버 코드와 시험, 데이터베이스 구조, 자동 배포, 등록 페이지 수정, 개인정보 안내 개정, 메일 문구(영어, 한국어), 사고 대응 순서.

## 8. 진행 순서와 중단 기준

| 단계 | 내용 | 끝났다는 기준 |
|---|---|---|
| 0 | 설계 승인, 계정 8단계 | 도메인이 열리고 `hello@` 로 메일이 들어옴 |
| 1 | 대기 명단을 새 서버로 | 시험 등록 10건이 확인 메일까지 통과, Gmail과 네이버에서 스팸함이 아닌 받은편지함 도착, 삭제 링크 동작, 안내문 개정 |
| 2 | 주간 글 발송을 같은 명단에서 | 월요일 발행이 승인 한 번으로 발송됨 |
| 3 (1월) | 회원, 메일 링크 로그인, 알림 발송, 결제 | 별도 설계 |

중단 기준: 1단계가 2주를 넘기면 멈추고 뉴스레터 서비스(C안)로 돌립니다. 출시 전 시간은 카드 품질과 예측 채점 기록에 쓰는 편이 결제 확률에 더 직접 닿습니다.

1단계를 연 뒤 볼 숫자: 확인 비율(등록 대비 확인), 반송 비율, 막힌 봇 수, 삭제 요청 수.

## 9. 확인하지 못한 것

- Workers 무료 요금제에서 하루 한 번 정리 작업(예약 실행)을 돌릴 수 있는지. 가격 페이지에서는 확인하지 못했습니다. 안 되면 등록 요청이 들어올 때 정리를 같이 돌리는 방식으로 바꿉니다.
- 도메인 가격과 원하는 이름을 살 수 있는지.
- 한국 법 조문(개인정보 보호법 시행령 40조, 정보통신망법 50조)과 미국 CAN-SPAM의 우편 주소 요건은 조문을 직접 대조하지 않았습니다. 첫 안내 메일을 보내기 전에 변호사 확인이 필요합니다.
- 유럽 거주자가 등록할 때의 GDPR 의무(대리인 지정 등)는 검토하지 않았습니다.
- 확인 메일로 등록이 얼마나 줄어드는지는 근거 숫자가 없습니다. 열어 보고 잽니다.
- Supabase와 뉴스레터 서비스의 현재 요금은 이번에 다시 확인하지 않았습니다.
